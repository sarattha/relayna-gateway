## Study design

The release uses the [native two-pod adaptive search](https://github.com/sarattha/relayna-gateway/blob/main/benches/body-admission/README.md)
for **5, 10, 20, 40, 80 and 100 MiB** JSON, with at least **three fresh-pod trials
per confirmed setting**. Each pod has **2 CPUs / 1 GiB memory / 512 MiB serialized
body budget**. The committed final candidate is built before measurement.
No builds or competing load run alongside the measured search.

```sh
scripts/bench-body-admission --json doctor
scripts/bench-body-admission --json run --build \
  --body-mib 5 10 20 40 80 100 --repetitions 3 \
  --output target/release-benchmarks/v1.0.0-r3
```

Preflight on 25 October 2026 identified native **Apple M1 Pro / arm64** with
Docker Desktop allocated **10 CPUs / 20 GiB**. This is preflight information,
not measured run provenance. The completed report must record the actual
runtime commit, immutable image ID, harness revision/hashes, architecture,
hardware and resource allocation at execution time.

All six sizes use a fixed **180-second client observation window**, a
300-second condition-runner deadline and a 600-second outer trial deadline
including setup and evidence collection. The earlier 60-second ARM64 attempt
is retained as failed: at 2,048 requests per pod, unfinished requests were
cancelled before authentication and forwarding drained. An isolated diagnostic
with the same runtime, cohort and resource caps drained the 32-slot 10 MiB
trial in 77.4 seconds with 441 verified successes, no OOM/restart and 16 lost
denial responses exactly accounted for by admission counters. Both pods still
OOMed in its 1,024-slot trial. This diagnostic justifies the longer observation
window; it is not the repeated six-size release study. Transport errors remain
reported, and resource stability does not imply HTTP-clean delivery or a latency
SLO. The final run must use the same disclosed window for every size.

[Previous v0.1.49 study](v0.1.49.md) used native amd64 hardware. Any comparison
must disclose architecture, hardware, cohort and methodology differences.

search without an adjacent repeated resource failure remains a tested lower
bound, not a recommended production default.
