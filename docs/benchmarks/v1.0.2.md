# v1.0.2 release benchmark

Status: **pending committed-candidate execution; release blocked**.

Version 1.0.2 changes the production runtime to Debian 13 Distroless and mounts
static benchmark sampler tools from a separate init container. Fresh resource
and forwarding-latency evidence is required before merge, tagging or
publication. The previous version's measurements and the preparatory image
smokes do not satisfy this gate.

The release study will use `scripts/bench-body-admission` with full adaptive
searches for **5, 10, 20, 40, 80 and 100 MiB JSON**, at least three fresh-pod
trials per confirmed setting, two Gateway pods and per-pod limits of **2 CPUs /
1 GiB memory / 512 MiB serialized-body budget**. Native host, Docker, image and
kind architectures must match. The study must identify its committed runtime,
resolved image ID, harness, hardware, offered cohorts and all failures.

Pending evidence includes peak RSS/cgroup memory and headroom, success latency
p50/p95/p99, rejection latency, elapsed time, verified successes, admission 503s,
transport errors, OOMs and restarts. Missing or censored measurements will be
explicit. Repeated resource edges will be distinguished from finite lower
bounds, and observed edges will require production headroom.

Local downloads will be retained under `target/release-benchmarks/v1.0.2`.
Before merge, publish the full HTML/JSON/CSV, raw observations, checkpoints,
failed trials, provenance and checksums outside the application source tree,
then link their immutable archive and documentation-hosted URLs here. GitHub
release attachments remain only the changelog and SPDX SBOM.

Compare with [v1.0.1](v1.0.1.md) only where hardware, cohort and methodology are
comparable. The static sampler has different memory/CPU overhead and 10 ms
timestamp resolution; retain its image identity with the new results.
