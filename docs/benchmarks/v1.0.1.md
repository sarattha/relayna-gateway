# v1.0.1 release benchmark

Status: **measurement and evidence audit complete**. Fresh validation measured the committed v1.0.1 runtime on 26 October 2026 (UTC). Final-head CI and GitHub merge gates still apply.

The six full adaptive searches completed **212 fresh-pod trials**, including three HTTP-clean confirmations for each selected setting. OOM exploration and all transport failures remain in the evidence. These finite observations are not production slot recommendations.

## Runtime, harness and conditions

- Runtime and harness commit: `52c56f9104f43cb108b7ccd647f6911433f8dcfe`; clean checkout. It includes Manrope, monitoring readability fixes, Pingora 0.9.0 and the dependency-only compression patch. Later documentation/evidence commits do not change these measured build inputs.
- Native Linux **amd64** for the host, Docker, image and kind nodes; no emulation. Each size used a separate GitHub-hosted Ubuntu 24.04.5 runner, with four virtual CPUs and approximately 15.62 GiB Docker memory. CPU models differ below; these are not one homogeneous hardware cohort. Exact Docker resources, kernel/version and node identities are in the audit JSON.
- Two Gateway pods, **2 CPUs / 1 GiB memory / 512 MiB serialized-body budget per pod**, glibc mmap threshold 128 KiB, real PostgreSQL/Redis and direct pod endpoints. No production credentials or prompts are used.
- Full adaptive search for 5, 10, 20, 40, 80 and 100 MiB JSON, three fresh-pod trials per confirmed setting. Final offered cohort is **2,048 simultaneous requests per pod**. Initial cohorts vary by body size and expand during discovery; raw rows retain the actual offered cohort.
- Upstream pauses reads for ten seconds and delays its response for two seconds after upload. Each size uses a 180-second client deadline, 300-second condition deadline and 600-second outer trial deadline. The criterion is resource stability, not a latency SLO.
- Each workflow builds the same committed source with `--build`. The resolved image IDs differ across independent builds and are recorded individually. The benchmark builder labels the revision but leaves its image version label `unknown`; Cargo source version is 1.0.1. These source-built images are not the subsequently signed release image.

The workflow dispatch for each size was equivalent to:

```sh
scripts/bench-body-admission --json doctor
scripts/bench-body-admission --json run --build \
  --body-mib <5|10|20|40|80|100> --repetitions 3 \
  --output target/body-capacity
```

## Repeated resource observations

Memory is the largest individual-pod observation across the three selected trials. Headroom is 1,024 MiB minus the observed cgroup peak. Every selected trial has zero OOMs, restarts, transport errors, scrape errors and admission counter gaps; reservations drain to zero.

| JSON MiB | Slots/pod (3/3 clean) | Interpretation | Adjacent slots: OOM trials | Peak RSS / cgroup MiB | Headroom MiB |
| --- | ---: | --- | --- | ---: | ---: |
| 5 | 90 | tested lower bound | 91: 1/3 | 818.75 / 1012.22 | 11.78 |
| 10 | 44 | tested lower bound | 45: 1/3 | 793.84 / 1011.79 | 12.21 |
| 20 | 24 | tested lower bound | 25: 2/3 | 811.56 / 1024.00 | 0.00 |
| 40 | 11 | tested lower bound | 12: 1/3 | 773.50 / 1009.62 | 14.38 |
| 80 | 5 | tested lower bound | 6: 2/3 | 734.22 / 964.32 | 59.68 |
| 100 | 4 | confirmed resource edge | 5: 3/3 | 746.51 / 975.48 | 48.52 |

The original automated reports label all six results as edges under their observed-adjacent-OOM rule. This independent audit uses a stricter interpretation: **only 100 MiB has OOM in all three adjacent trials**. The other sizes remain tested lower bounds because adjacent OOMs are intermittent. Original observations and reports are retained unchanged; the published audited report applies this interpretation.

**The 20 MiB setting reached the 1,024 MiB cgroup peak with zero observed headroom**, despite surviving all three selected trials. Other selected settings also approach the pod limit. These settings must not replace the released defaults of eight slots and 512 MiB; choose deployment-specific headroom. The serialized-byte budget excludes JSON analysis, connection state, allocations and other process memory. Configured slots do not preallocate bodies.

## Separate fixed-slot latency sanity runs

The candidate and released v1.0.0 each completed three fresh-pod 5 MiB trials at eight slots/pod, 16 offered requests/pod and the same pod caps, ten-second read pause and two-second response delay. **They ran on different CPU models, so this is not a matched performance experiment. No latency delta, regression threshold or speedup is claimed.** End-to-end latency includes upload, scheduling and the deliberate upstream delay; it is not isolated proxy overhead.
