# v1.2.0 release benchmark

Status: **measurement and evidence audit complete**. Fresh validation measured
runtime `14c42c72eda1358ff26600631ed5f47b3813970c` on 6 November 2026 (UTC). Final-head CI and GitHub merge gates
still apply. Later documentation and test-scheduling commits do not change the measured runtime inputs.

The six adaptive searches completed **254 fresh-pod trials**,
with at least three resource-stable confirmations at each selected setting.
Resource stability permits separately reported lost admission replies when every
request reconciles to a verified success or a server-side admission denial.
It does not imply HTTP-clean delivery, a latency SLO or a safe production setting.

## Runtime, harness and conditions

- Runtime and harness: [14c42c72eda1](https://github.com/sarattha/relayna-gateway/commit/14c42c72eda1358ff26600631ed5f47b3813970c), clean checkout; Cargo version 1.2.0. The source-built images label the revision but their version label is `unknown`. They are distinct from the signed image subsequently built for the release tag.
- Native Linux **amd64** for host, Docker, image and kind nodes, without emulation. Each size uses a separate Ubuntu 24.04 runner; CPU models and Docker resources are recorded below. Separate runners are not a matched hardware cohort.
- Two Gateway pods, each **2 CPUs / 1 GiB memory / 512 MiB serialized-body budget**, real PostgreSQL/Redis, direct pod endpoints and the production Distroless image. External digest-pinned BusyBox sampler tools are mounted only in benchmark pods, with centisecond timestamps and nominal 250 ms sampling. Cgroup peaks and sampled process RSS measure different things.
- Standard fixed body-slot mode with adaptive configuration search, not opt-in elastic/working-memory admission. Authentication/source controls remain enabled. Early denials can prevent body slots filling; configured ceilings are not occupied concurrency.
- Exact JSON sizes 5, 10, 20, 40, 80 and 100 MiB; at least three fresh-pod confirmations; finite search ceiling 4,096 configured slots/pod. Actual offered cohorts and occupied body counts are retained for each trial.
- The upstream pauses reads for ten seconds and waits two seconds after upload before replying. Client, condition and outer trial deadlines are 180, 300 and 600 seconds. Successful latency includes upload, scheduling and these deliberate delays; it is not isolated Gateway overhead.
- No production credentials, prompts or OpenAI calls. Bootstrap tokens and registered-service credentials are generated for the isolated experiment and excluded from exported evidence.

Each full workflow used the equivalent of:

```sh
scripts/bench-body-admission --json doctor
scripts/bench-body-admission --json run --build \
  --body-mib <5|10|20|40|80|100> --repetitions 3 \
  --output target/body-capacity
```

## Repeated resource observations

Memory is the largest individual-pod observation across selected confirmations.
Headroom is 1,024 MiB minus observed cgroup peak. Selected trials have no OOMs,
restarts or censored memory; reservations drain to zero and admission counters
reconcile. HTTP-clean counts and transport errors remain explicit below.

| 100 | 37 | 3 / 3 | 37 | tested lower bound | 38: 1/3 | 948.25 / 1002.95 | 21.05 |

The audited edge label requires OOM in **every** repeated adjacent trial and no
failure at a lower tested slot count. Intermittent adjacent OOMs or a finite
ceiling remain tested lower bounds. Settings selected from repeated trials take
precedence over higher one-off discoveries. Do not interpret high configured
ceilings with lower occupied-body counts as maximum body concurrency.

Occupied counts include requests still reading their bodies; they do not imply
that many complete JSON bodies fit simultaneously. The serialized-body arithmetic
bound is `floor(512 / JSON MiB)`. The 10 MiB confirmation with two transport
errors reconciles both to server-side admission denials and is excluded from the
HTTP-clean count.

These resource boundaries require production headroom. Serialized bytes exclude
parsing, connection state and other process allocations. Keep the released defaults
of eight slots and 512 MiB unless deployment-specific evidence supports tuning.

## Superseded attempts

The first six-size study targeted `dda8c5ddf1b8f9b325087bb9893c839a43fc9d46`.
The 5 MiB job completed but its first Gateway pod restarted before load with a
bootstrap-token store error. A deterministic PostgreSQL integration test reproduced
the same-token unique-prefix race, failed before the fix and passed afterward.
The fix preserves the existing winning token and fails closed when no active token
exists. The report selector was also corrected to prefer repeated stable settings,
and fixture readiness now probes PostgreSQL over TCP.

The other five original searches were cancelled once this runtime fix became
necessary. Their partial/failed checkpoints, the original 5 MiB comparison and
all observations remain in the superseded bootstrap archive. None qualifies this release or
is combined with the final candidate. The second attempt measured `d21547e1b9bff7e4ce9da9810eb099885ef2c7d1`.
Its same-runner comparison completed, but image CI found two newly reported zlib
CVEs in the unchanged pinned base. The actual library was replaced with Debian's
checksum-pinned fixed package. Narrow, versioned scanner exceptions handle the
Debian 13 suite's lack of a fixed-version record and expire on 6 December 2026;
the old image still fails the gate. See [image-security evidence](../runtime-image-security.md#v120-zlib-update).
The six in-progress searches were cancelled and retained in the superseded zlib
archive. The third attempt measured `58cc984b962ecd65c0f70e3a5fb9c665373695d5`
and completed 239 resource trials plus the same-runner comparison. PR review
then found that rewrite serialization could reduce the input workspace charge
while original bytes and parsed JSON were still live. Two regression tests failed
before the correction; the fix separates output capacity, preserves input extent,
keeps failed growth atomic and retains output through forwarding. Additional tests
cover small-reserve promotion and cleanup. The complete pre-review study remains
in its [immutable archive](https://github.com/sarattha/relayna-gateway/tree/9d3d2ce3b876dbaea1e7e3390edac6bdda79e4a5)
and [pinned documentation](https://github.com/sarattha/relayna-gateway/blob/af313e7975481eba8991326b810e962b8d850569/docs/benchmarks/v1.2.0.md).
All six adaptive searches and the same-runner comparison were freshly repeated
on the corrected runtime above. No earlier attempt qualifies this candidate.

## Verification and retained evidence

The full local verification stack passes, including fmt, Clippy, workspace tests,
543 Nextest cases with no skips, nine vendor tests, audit/deny/machete, Trivy,
Gitleaks and Semgrep. The workspace build, UI build/tests/typecheck/coverage,
29 benchmark harness tests, 12 monitoring fixture tests, strict docs and metadata
validation pass. Both [push](https://github.com/sarattha/relayna-gateway/actions/runs/42194016536)
and [PR](https://github.com/sarattha/relayna-gateway/actions/runs/42194024417) CI passed
on the measured runtime, including actual production-image checks, vulnerability
gates and the continuous ten-minute HTTP/SSE/WebSocket and Usage monitor. Later
documentation commits must pass final-head CI before merge. No 24-hour soak is claimed.

A CI Nextest run exposed CPU contention between separate full-cost Argon2 tests:
proof verification exceeded the production one-second deadline. The follow-up
`.config/nextest.toml` reserves the test runner for each authentication unit test.
Their internal concurrency, real hash parameters and all rejection/deadline
assertions remain intact. All 22 authentication tests passed three repeated local
runs (66 executions); the full verification stack was then rerun. This scheduling
fix is included in the measured candidate. The final full verification stack
also covers the rewrite-accounting correction; production hash costs and
admission deadlines were not relaxed. Verification evidence is archived
separately.

Evidence lives outside the application source tree in the immutable
[v1.2.0 artifact archive](https://github.com/sarattha/relayna-gateway/tree/492a5db9138f807874e6893201949722b86e68ba).
The docs workflow verifies its SHA-256 manifest before publishing it. The archive
is available before merge; hosted links deploy from main after merge. Release
attachments remain only `CHANGELOG.md` and the SPDX SBOM.
