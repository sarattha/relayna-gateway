# v1.2.0 release benchmark

Status: **fresh validation required after the rewrite-accounting review fix**.
Do not merge, tag or publish this version until the corrected committed runtime
has completed the full six-size study and its evidence audit.

Review of PR #146 found that serializing a chunked rewrite could reduce the
input's working-memory reservation while the original bytes and parsed JSON
were still live. The correction preserves the input extent, reserves output
capacity separately, and keeps failed growth atomic. Tests cover unknown and
underestimated lengths, both admission modes, protected small-body capacity,
and forwarding/drop cleanup.

The completed pre-review study measured runtime
`58cc984b962ecd65c0f70e3a5fb9c665373695d5`: 239 fresh-pod capacity trials plus a
same-runner v1.0.2 comparison. Those observations remain intact, but they do not
qualify the corrected runtime. See the
[pinned pre-review record](https://github.com/sarattha/relayna-gateway/blob/af313e7975481eba8991326b810e962b8d850569/docs/benchmarks/v1.2.0.md)
and [immutable evidence archive](https://github.com/sarattha/relayna-gateway/tree/9d3d2ce3b876dbaea1e7e3390edac6bdda79e4a5).
Both earlier superseded attempts are retained there as well.

The replacement study must use native matching architectures, 5/10/20/40/80/100
MiB exact JSON, two pods each limited to 2 CPUs / 1 GiB memory / 512 MiB serialized
bytes, full adaptive search and at least three fresh-pod confirmations per
selected setting. Runtime/image/harness identity, hardware, offered cohorts,
latency, memory, failures and checksums must be published before release.
Benchmark reports remain in documentation hosting, outside release attachments.
