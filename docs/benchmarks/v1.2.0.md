# v1.2.0 release validation

Status: **release validation in progress; not ready to merge, tag or publish**.

Version 1.2.0 combines PR #146's processing, authentication and admission
changes with v1.0.2's Distroless packaging. A fresh committed runtime candidate
must complete the six-size adaptive release study. Previous PR observations
and the v1.0.2 owner waiver do not qualify this version.

## Required execution

Use `scripts/bench-body-admission run --build` on native amd64 or arm64 for
5, 10, 20, 40, 80 and 100 MiB JSON, omitting `--slots` to run the full adaptive
search and using at least three fresh-pod trials per confirmed setting.
Each trial uses two Gateway pods, each capped at 2 CPUs, 1 GiB memory and
512 MiB serialized-body capacity. Authentication/source controls remain enabled.
Record their denials separately: early limits can prevent body slots filling.

Record the final runtime commit, resolved images, exact harness hashes,
host/CPU/Docker/node provenance, offered cohorts, selected settings, failures,
latency distributions, verified outcomes, OOMs, restarts and memory headroom.
Retain original observations and checkpoints under
`target/release-benchmarks/v1.2.0`; publish audited HTML/JSON/CSV and raw evidence
with checksums outside the application source tree through documentation hosting.

The record will be completed with measured results and durable evidence links
before release. A controlled forwarding-latency comparison and final-candidate
verification, actual-image tests, ten-minute protocol monitoring and PR gates
also remain required. No new capacity or performance result is claimed here.

## Compatibility

The compatibility boundary is released v1.0.2. No PostgreSQL or Redis migration
is introduced. Default body limits remain eight slots and 512 MiB. Optional
elastic admission, source limits and Linux memory protection are described in
the [upgrade guide](../deployment.md#upgrade-to-120). An observed resource edge
is not a safe production setting, and historical comparisons must disclose
changes in architecture, host resources, sampler method and admission behavior.
