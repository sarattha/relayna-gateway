# v1.3.0 release benchmark

Status: **six-size measurement and evidence audit complete**. Fresh native
amd64 validation measured runtime `4d25895cb8d45ad24a6978d234f3bb7f96b2b177`
on 14 November 2026 (UTC), Cargo version **1.3.0**. The six adaptive searches
completed **207 fresh-pod trials**, with three resource-stable confirmations
per selected setting. Final-head CI, the controlled comparison below and
required GitHub reviews still apply before merge. Later SQLx maintenance docs
and Nextest test scheduling do not change the measured production inputs.

The 10 MiB study establishes a repeated resource edge. The other five sizes
establish tested lower bounds because adjacent OOMs were intermittent.
Resource-stable trials may include lost denial replies when every offered
request reconciles to a verified body success or a server admission denial;
HTTP-clean delivery is reported separately. These are observed boundaries,
not recommended production settings or a latency SLO.

## Runtime, harness and protocol

- Runtime and harness: [4d25895cb8d4](https://github.com/sarattha/relayna-gateway/commit/4d25895cb8d45ad24a6978d234f3bb7f96b2b177), clean source builds. Images identify the exact source revision; their version label is `unknown`. They are benchmark builds, separate from a subsequently signed release image.
- Native Linux amd64 for host, Docker, images and kind nodes, without emulation. Six separate Ubuntu 24.04.5 runner hosts; hardware and resources appear below. They are not one matched hardware cohort.
- Two fresh Gateway pods per trial, each **2 CPUs / 1 GiB / 512 MiB serialized-body budget**, real PostgreSQL/Redis, and the production Distroless image. Authentication and source controls stay enabled. Optional size-aware/elastic modes are unset; the adaptive search varies the fixed configured body-slot ceiling.
- Exact 5/10/20/40/80/100 MiB JSON, simultaneous offered cohorts, no TLS, compression or retries, direct pod endpoints rather than ingress. A streaming mock checks length/hash and credential stripping. The mock pauses reads for ten seconds and waits two seconds after upload; success latency includes these deliberate delays.
- Client, condition and outer trial deadlines are **180 / 300 / 600 seconds**. Process RSS and cgroup memory are separate measures; digest-pinned BusyBox sampling uses nominal 250 ms intervals and 10 ms timestamp resolution. Censored peaks from resource failures remain in raw evidence.
- Every reported selected confirmation has complete two-pod memory evidence, zero OOMs/restarts, verified successes and admission gauges drained to zero. Credentials and kubeconfigs are excluded from publication. No production provider requests or prompts were used.

Each per-size workflow used:

```sh
scripts/bench-body-admission --json doctor
scripts/bench-body-admission --json run --build \
  --body-mib <5|10|20|40|80|100> --repetitions 3 \
  --output target/body-capacity
```

## Repeated resource observations

Memory is the maximum individual-pod observation across the selected three
confirmations. Headroom is 1,024 MiB minus observed cgroup peak.

| JSON MiB | Selected slots/pod | Stable / HTTP-clean trials | Peak occupied bodies/pod | Interpretation | Adjacent OOM trials | RSS / cgroup peak MiB | Headroom MiB |
| --- | ---: | ---: | ---: | --- | --- | ---: | ---: |
| 5 | 104 | 3 / 3 | 104 | tested lower bound | 105: 1/3 | 928.09 / 1018.78 | 5.22 |
| 10 | 48 | 3 / 2 | 48 | confirmed resource edge | 49: 3/3 | 949.62 / 1019.80 | 4.20 |
| 20 | 54 | 3 / 3 | 54 | tested lower bound | 55: 1/3 | 944.05 / 1017.63 | 6.37 |
| 40 | 50 | 3 / 3 | 50 | tested lower bound | 51: 2/3 | 950.54 / 1014.42 | 9.58 |
| 80 | 32 | 3 / 2 | 32 | tested lower bound | 33: 1/3 | 973.47 / 1019.27 | 4.73 |
| 100 | 43 | 3 / 3 | 43 | tested lower bound | 44: 1/3 | 956.83 / 996.06 | 27.94 |

The audit reanalyzes all 207 raw trials and requires at least three stable
confirmations, OOM in every repeated adjacent trial, and no contradictory
lower-slot resource failure at the same cohort to label a confirmed edge.
Original harness reports require only one adjacent OOM; the published audited
report conservatively corrects those labels without changing observations.
Original reports and all failed trials are preserved in the raw archive.

Occupied bodies include partial uploads, not only complete JSON payloads.
The complete-body arithmetic bound is `floor(512 / JSON MiB)`; a configured
slot ceiling can be much higher while byte admission and early auth/source
denials reject most traffic. **Keep production headroom**: selected observations
leave only 4.20–27.94 MiB in the pod. Retain defaults of eight body slots and
512 MiB unless workload-specific evidence supports other settings.

## Comparison with v1.2.0

The [v1.2.0 six-size study](v1.2.0.md) used separate hosted runners with other
CPU models, Docker resources and offered-load paths. The nominal pod caps and
body sizes match, but these are not matched hosts. The selected configured
slots vary in both directions; do not interpret those differences as a measured
speedup or regression. Keep the older evidence unchanged.

A same-runner controlled comparison is running in
[workflow 43596307023](https://github.com/sarattha/relayna-gateway/actions/runs/43596307023):
native amd64, 5 MiB JSON, eight slots per pod and three fresh-pod trials for
each version. The candidate is source-built from test-scheduling head
`2985a614aa3afda44f32975d90b34f40acb583ce`; production inputs are unchanged
from the six-size candidate. The baseline is immutable v1.2.0 image index
`sha256:a22c3d850ab2c7320d4bf87ce83adf0fa3deb90496fba6a8227a6eea9d885cbf`.
Its result and durable evidence audit are **pending**; keep this PR in draft
until this final release-checklist measurement is complete. No relative
latency claim is made yet.
