# v1.3.0 release validation

Status: **pending fresh measurement and evidence publication**. This version
must not merge, be tagged or be published until the required six-size resource
study and its documentation are complete. No new capacity result is claimed.

## Candidate and protocol

Version 1.3.0 adds [LiteLLM customer usage and costs](../litellm-customer-usage.md).
The versioned runtime candidate must be committed before measurement. Record
its full commit and each resolved image ID/digest with the completed results;
any later runtime/build-input change requires a new run.

Run separate native amd64 source-built adaptive searches for **5, 10, 20, 40,
80 and 100 MiB JSON**, with at least **three fresh-pod trials per confirmed
setting**, two Gateway pods and per-pod **2 CPU / 1 GiB memory / 512 MiB
serialized-body budget**. Use the unchanged source harness:

```sh
gh workflow run body-admission-benchmark.yml --ref t3/litellm-customer-cost-usage \
  -f architecture=amd64 -f mode=full -f body_mib=<size>
```

Store downloaded original evidence under
`target/release-benchmarks/v1.3.0`, then publish it through documentation
hosting from an immutable evidence archive outside the application source tree.
Preserve failures, checkpoints, raw observations and checksums. Hosted Actions
artifacts are temporary collection points, not the final durable publication.

## Outstanding evidence

Execution date, exact runtime/harness commits, image IDs, per-size workflow
identities, host/CPU and Docker resources remain pending. No memory, latency,
throughput, occupied-body, denial, OOM, restart or transport-error values have
been measured for this version yet. Completion requires the full record
specified in the [release protocol](index.md#add-the-next-version), interactive
HTML reports and raw JSON/CSV links, including failed and censored trials.

The [v1.2.0 results](v1.2.0.md) describe a different committed runtime and are
retained as history. Comparisons require matching conditions and explicit
hardware/cohort/method differences. Synthetic million-customer UI and export
checks verify bounded application work; they do not replace release capacity
measurements or establish LiteLLM database performance.
