# Gateway 1.0: see the system, follow the request

**Route intelligence. Keep control.**

Gateway 1.0 brings a shared operating view to HTTP, streaming responses and
long-lived WebSockets. Admin and Owner pages share consistent navigation and
controls, with light, dark and system appearance.

!!! info "Released October 25, 2026"
    [Gateway 1.0.0](https://github.com/sarattha/relayna-gateway/releases/tag/v1.0.0)
    links to the published [release evidence](benchmarks/v1.0.0.md).
    This documentation hosts the screenshots and checksums. Screenshots use
    illustrative synthetic data and are separate from performance measurements.

## Choose the question, then the workspace

| Workspace | Start here | What it helps you decide |
| --- | --- | --- |
| **Monitor** | Overview → Traffic → Usage & cost → Health | Is the gateway available? What is active? Where are failures, cost or capacity pressure? |
| **Discover** | Projects → Services → Providers → Routes | Which resources are connected, which transports are configured, and how will a request be routed? |
| **Govern** | Virtual keys → Policies & guardrails → People & identities → Audit → Settings | Who can call what, under which safeguards, and who changed the configuration? |
| **Owner** | My services / My projects → resource dashboard | What is happening within the exact resources assigned to this identity? |

Charts answer comparisons; tables retain exact values. A configured connection
is distinct from a healthy connection. A returned page is distinct from a
lifetime total. An unknown observation is distinct from a measured zero.

## Monitor: from fleet pressure to one request

### Health: current capacity and recorded reliability

The Gateway pulse combines request-rate observations, body-slot and byte meters,
protocol mix and latency distributions. Select a process to isolate pressure;
select all reporting instances to inspect known fleet coverage. Partial or stale
publishers stay explicit. Recorded provider reliability remains a separate
24-hour view.

### Traffic: active requests, open sessions and recent completions

Choose HTTP/SSE or WebSocket, then Active or Recent. Open sessions remain
independent of completed-request eviction. Recent history defaults to completion
time so an old socket closed moments ago is discoverable. Inspect opens the
sanitized lifecycle, upstream timings and recorded identity. Older pages stay
fixed through Pause/Resume.

### Usage: bounded first, detail on demand

Start with All projects / Last 24 hours. Summary, trends and recent events load
independently; choose a breakdown when you need it. Applying a range freezes it
for page traversal. Cursor history preserves insertion membership; historical
repricing and retention can still change existing values. Large bounded exports
stream without accumulating the entire file in browser memory.

Service and project dashboards combine incident trends, service-version markers,
ranked usage and request investigation. Missing time buckets remain gaps.
Version observations describe when Gateway saw a value, not a deployment
history. Backend authorization retains exact service/project membership.

## Appearance that follows the work

Light / Dark / System controls are available on sign-in and in the sidebar.
Theme changes preserve filters, page position and unsaved inputs. Actionable
controls lift subtly; reduced motion removes movement. Desktop and mobile use
the same workflows, with horizontal scrolling for wide evidence tables and
visible keyboard focus.

Read the [Admin portal guide](admin-portal.md) for setup, drawers and contextual
help.

## Roll out with evidence

Follow the [1.0 upgrade checklist](deployment.md#upgrade-to-100) for the three
additive migrations, index-build maintenance, fourteen PostgreSQL connections
per store/replica and rollback constraints. The major version retains the
released v0.1.49 API, key, provider, streaming and accounting contracts.

[Release validation](benchmarks/v1.0.0.md) identifies the final runtime and
harness, six-size body-admission study, continuous ten-minute protocol CI check,
forwarding-latency comparison and durable raw evidence. A 24-hour soak remains
an optional, intentionally started manual run. Synthetic screenshots demonstrate the
interface; they do not establish production capacity.
